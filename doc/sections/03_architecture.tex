\section{라이브러리 구조와 핵심 모듈 (Architecture)}

\subsection{디렉터리 구조}
\begin{lstlisting}[style=cstyle,caption={핵심 디렉터리 개요}]
include/oqs/   # public API headers
src/common/    # common crypto utilities (AES/SHA/RNG/memory)
src/kem/       # KEM interface and algorithm implementations
src/sig/       # signature interface and algorithm implementations
tests/         # KAT and helper-based validation code
build/lib/     # static library outputs
\end{lstlisting}

\subsection{레이어 관점}
\begin{itemize}[leftmargin=*]
\item API Layer: \texttt{include/oqs/*.h}
\item Dispatch Layer: \texttt{src/kem/kem.c}, \texttt{src/sig/sig.c} (알고리즘 식별자 매핑, 객체 생성)
\item KEM Algorithm Layer: \texttt{src/kem/hqc/*}, \texttt{src/kem/ml\_kem/*}
\item SIG Algorithm Layer: \texttt{src/sig/ml\_dsa/*}, \texttt{src/sig/slh\_dsa/*}
\item Utility Layer: \texttt{src/common/*} (메모리/난수/해시/대칭키)
\end{itemize}

\subsection{KEM/SIG 디스패치 모델}
\texttt{OQS\_KEM\_new(method\_name)}와 \texttt{OQS\_SIG\_new(method\_name)}는
문자열 식별자를 기반으로 알고리즘 인스턴스를 생성한다.

KEM 경로에서는 생성된 \texttt{OQS\_KEM} 구조체의 길이 필드와 함수 포인터를 통해
\texttt{keypair}, \texttt{encaps}, \texttt{decaps}를 공통 방식으로 호출한다.
SIG 경로에서는 생성된 \texttt{OQS\_SIG} 구조체를 통해
\texttt{keypair}, \texttt{sign}, \texttt{verify}를 공통 방식으로 호출한다.
